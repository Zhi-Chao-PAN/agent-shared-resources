# 设计、状态与恢复

管理器只发布选择过的 Skills / MCP 声明，不运行模型，不改变账号、approvalPolicy、默认权限、模型、原生插件或全局 Agent 指令。连接器可提供写入工具，但业务写入仍由客户端与当次用户授权决定；本工具不是权限隔离层。

## 目录边界

仓库包含源码、锁文件、四个带许可证的技能源、示例、测试和文档。个人选择放在被 Git 忽略的 `agent-resources.local.json`。原生客户端入口保留在原位置。

`~/.agent-shared-resources/` 保存发布回执、待完成事务、备份、MCP OAuth 缓存及可选公开浏览器产物。macOS / Linux 创建私有目录 0700、私有文件 0600；Windows 权限继承当前用户目录的 NTFS ACL，不声称 POSIX mode 能替代 Windows ACL。不要把这个目录上传、放进公共共享目录，或在用户之间同步。

Skills 使用复制发布，减少 Windows 符号链接权限、外置盘掉线和跨客户端扫描差异。源内容、已发布副本和回执的内容哈希可核对。大依赖、模型和浏览器不应放在 Skill 目录里；单个技能源上限 20 MiB。发布不自动执行里面的脚本。

## 配置保留

JSON/JSONC 用目标键编辑，保留注释；TOML / DSH YAML 用带名称的独立受管块。DSH 的 `!!js` 标签只作不透明文本解析，不执行。每次变更比较除目标条目之外的语义状态，同名不同内容拒绝覆盖。原生文件路径中的 symlink/junction、重复 JSON 键、重叠目标与非普通文件也拒绝。

相同的既有技能或连接器不归本工具所有。后续用户更改过的受管条目也不强行回滚；请先保留你的修改并人工核对。不会把备份的整份客户端设置覆盖回去。

## 发布与中断

1. 对所选资源全部预检，再取得用户状态目录里的独占发布锁。
2. 先保存含前后状态的准备事务，再依次原子替换文件或发布完整 Skill 目录。
3. 每步读回，最后提交新回执。原生文件变更前会保留本地备份。

中断后 `plan/apply/rollback` 停止并要求 `recover`。恢复仅在目标仍与记录的 before 或 after 完全一致时继续。原生文件有其他修改时停止，保留现场。若来源改变或暂存副本不完整，也停止；将提示的暂存目录另存核对后，才能决定如何处理。

发布锁只协调本工具的进程，不能冻结客户端自身。进行发布/回滚时不要同时在客户端编辑设置。Windows 若客户端持有文件导致替换失败，结束设置编辑后再恢复。工具不杀客户端、不重启任务、不自动删除所谓“过期锁”；确认没有发布进程运行后才人工处理残留锁。

## 维护范围

首版不会自动更新已发布内容。更新源或 MCP 参数时，对对应资源明确 `rollback` 后再 `apply`；保留副本与私有配置的冲突判断。恢复材料是本机私有状态，不是可携带的安装包。

一个 CLI 检查结果不能替代原生模型验收：新会话应实际发现资源、加载一个 Skill 正文、执行最小只读 MCP 调用。正式写入另按具体任务授权，不为验收创建业务数据。
